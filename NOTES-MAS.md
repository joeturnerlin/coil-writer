Build env the script reads (keep profile files outside the repo; never commit them):

- `package:mas`: `COIL_MAS_PROFILE` (path to the Mac App Store `.provisionprofile`), `COIL_MAS_IDENTITY` (certificate name, e.g. `Apple Distribution: <name> (<TEAMID>)`).
- `package:mas-dev`: `COIL_MAS_DEV_PROFILE`, `COIL_MAS_DEV_IDENTITY` (development profile and certificate; an arm64 build for sandboxed local testing).

`mas.identity` in `package.json` is a deliberately invalid placeholder. The `mac` block's `identity: null` is inherited by `mas`, which would otherwise make a mas build silently skip signing; the placeholder makes a direct `electron-builder --mac mas` fail instead.

Changed on purpose: `fileAssociations` was removed from `package.json` and the same document type now comes from `mac.extendInfo.CFBundleDocumentTypes`. electron-builder appends generated entries to `extendInfo` entries, so keeping both produced two entries, and the generated one cannot carry `LSItemContentTypes`. The `.fountain` association is otherwise identical (name, role Editor, rank Default, icon). electron-builder emits no `mimeType` into the macOS plist, so nothing is lost.

Fixes already settled in config, no entitlement placeholders needed: `@electron/osx-sign` adds `com.apple.application-identifier` and `com.apple.developer.team-identifier` itself from the embedded provisioning profile (its `preAutoEntitlements`). So there is no team id for you to paste into the plists.

## Engineering notes per finding

- M-02 network: `network.client` is in. The hosted tester proxy and provider calls are outbound HTTPS from the main process, so no server entitlement.
- M-03 files: `files.user-selected.read-write` covers File > Open, Save As, and files Finder opens through `open-file`. No security-scoped bookmarks are needed today because paths are not persisted (only main holds paths, by opaque id, for the process lifetime). A "reopen last file" feature WOULD need bookmarks: `showOpenDialog`/`showSaveDialog` with `securityScopedBookmarks: true`, store the returned bookmark, and bracket reads/writes with `app.startAccessingSecurityScopedResource(bookmark)` and the returned stop function (all present in the installed Electron typings, platform `mas`). Window state in `userData` is inside the container and needs nothing.
- M-03b: paths arriving through `second-instance` argv (command line) are NOT sandbox-granted. Under MAS, `open -a Coil file.fountain` goes through `open-file` and works. A raw argv path to a file the user did not pick would fail to read. Command-line launches are not an App Store use case; no code change made.
- Printing: `window.print()` is used (`src/components/Toolbar.tsx`, `src/lib/desktop.ts`), so `com.apple.security.print` was added. UNVERIFIED that the print dialog works in the sandbox until a signed mas-dev build is run.
- M-05 single instance: macOS itself enforces one instance for Finder launches and delivers `open-file`. The installed Electron typings say `requestSingleInstanceLock` matters for command-line launches and say nothing MAS-specific. UNVERIFIED: how the lock behaves in a sandboxed MAS build (the lock is in `desktop/main.ts:15`; if it ever returned false in the sandbox the app would quit on launch). Test this first in a signed `mas-dev` build; if it misbehaves, the fix is to skip the lock when `process.mas` (typings: `process.mas` is true in MAS builds). Not changed here because `desktop/main.ts` was out of scope.
- M-06 fuses: installed `electron-builder` 26.15.3 supports a top-level `electronFuses` object (runAsNode, enableCookieEncryption, enableNodeOptionsEnvironmentVariable, enableNodeCliInspectArguments, enableEmbeddedAsarIntegrityValidation, onlyLoadAppFromAsar, loadBrowserProcessSpecificV8Snapshot, grantFileProtocolExtraPrivileges, resetAdHocDarwinSignature) using `@electron/fuses` 1.8.0. It is not per-platform, so putting it in `package.json` would also change the `dir` build the Playwright tests drive; hence CLI-only in `package-mas.mjs`. Not set: `enableCookieEncryption` (one-way, app uses IndexedDB not cookies) and `enableEmbeddedAsarIntegrityValidation` (experimental; decide separately). `RunAsNode` off means `child_process.fork` of Electron itself would break; grep of `desktop/` and `src/` found no fork/spawn/utilityProcess use.
- M-07 arch: `package:mas` passes `--universal`. A universal MAS pack was NOT built (only arm64 unsigned). UNVERIFIED: that the universal merge (x64 + arm64 asar merge) completes and signs cleanly. Fallback if it does not: build arm64 and x64 separately; App Store Connect takes one build per version, so a universal binary is the simple path.
- Electron's default Info.plist ships usage strings (camera, microphone, Bluetooth, audio capture) and an `NSAppTransportSecurity` block with `NSAllowsArbitraryLoads: true`. Coil asks for none of those capabilities. UNVERIFIED whether App Review flags them; trimming them needs `extendInfo` nulls plus a check, and was not done.
- Copyright string currently renders as `Copyright © 2026 Coil` (electron-builder default from `author`). JT: decide the legal name and set `build.copyright`.
- UTI risk: `art.coil.writer.fountain` is our own identifier. If another installed app also declares `.fountain`, Launch Services may resolve the extension to that app's type. UNVERIFIED whether a community-standard Fountain UTI exists; none was invented or adopted.
- File > Open Recent (`desktop/main.ts`, `rememberRecent`): uses `app.addRecentDocument` plus the `recentDocuments` menu role, correct for the non-MAS build. UNVERIFIED and NOT implemented: under the MAS sandbox a recent item is only reopenable if the app holds a security-scoped bookmark for it (`dialog.showOpenDialog({ securityScopedBookmarks: true })` returns `bookmarks`; `app.startAccessingSecurityScopedResource` on reopen, persisted by us). macOS may still grant access to items it launches via `open-file` from the system recents; confirm on a signed build before adding bookmarks.
- Version numbers: `version` (0.1.0) becomes `CFBundleShortVersionString` and is what testers see. `build.mas.bundleVersion` ("1") becomes `CFBundleVersion` and MUST increase on every upload for the same version (App Store Connect rejects a repeated build number: UNVERIFIED wording, rule per Apple docs recalled from memory). Bump it before each `package:mas`; Claude can do that.
